# Worm Clicker

Автокликер для браузерной игры с розовым пиксельным червём. Схема работы: запускаете программу,
один раз кликаете по червю сами, он прыгает, программа понимает, что это цель, и дальше кликает
по нему без остановки. Используется компьютерное зрение (OpenCV, без нейросетей).

* **Цель — только движущийся маленький розовый объект.** Неподвижные элементы страницы (розовый
  текст, кнопки, картинки, даже статичная копия червя) игнорируются и в превью не помечаются.
* **Клики идут непрерывно.** Прыжка между кликами программа не ждёт. Интервал настраивается в
  миллисекундах: от «максимум» (по умолчанию) до 1, 5, 10, 50, 100 мс и больше.
* **Превью встроено в главное окно и включено по умолчанию.** Оно обновляется с частотой 60 кадров/с
  (можно 30, 90 или 120; в `config.json` — до 144) и показывает только саму цель.
* **Запасной способ — «по образцу».** Обведите червя мышью прямо на превью (или наведите на него
  курсор и нажмите **F8**). Программа запомнит, как он выглядит, и будет находить его даже
  неподвижным.
* **F6** — старт/стоп (работает и тогда, когда в фокусе браузер), **F7** — аварийная остановка,
  **F8** — захват цели под курсором. Все клавиши можно переназначить.
* Есть тестовый режим без кликов, честная статистика, поддержка нескольких мониторов (в том числе с
  отрицательными координатами) и разного масштаба DPI. Есть локальная тренировочная мишень
  `practice/index.html`.

> ⚠️ **О правилах игры.** Многие игры с таблицами лидеров запрещают автоматизацию. Прежде чем
> использовать программу в рейтинговой игре, прочитайте правила сайта: за бота могут обнулить
> результат или заблокировать аккаунт. Программа не обходит античит и защитные механизмы сайта,
> не изменяет страницу и не перехватывает сетевой трафик. Она смотрит на экран и двигает мышь,
> как обычный пользователь.

## Что нового во второй версии

| было (v1) | стало (v2) |
|---|---|
| после клика программа ждала прыжка и только потом кликала снова | клики идут непрерывно; прыжок не ждётся |
| скорость не настраивалась (был только лимит кликов/с) | интервал между кликами в мс: ползунок, быстрые кнопки, точное поле |
| отладка в отдельном окне, выключена, ~4 кадра/с | превью встроено в главное окно, включено, 60 кадров/с (до 144) |
| «червём» считался любой розовый объект, похожий на спрайт | цель — только то, что **двигается**: вы кликаете по червю, он прыгает, программа его запоминает |
| в отладке были все кандидаты и подписи «???» (OpenCV не умеет рисовать кириллицу) | показывается только цель; надписи рисует интерфейс, а не OpenCV |
| светлые поля ввода с белым текстом, который было не прочитать | своя тёмная тема без системных полей ввода; весь текст контрастный |
| калибровка цвета по курсору | «по образцу»: обвести червя на превью или F8 — запоминаются цвет, размер и форма |

Исправлено также:

* интервал больше не «уплывает» — клики идут по расписанию (50 мс дают ровно 20 кликов/с, а не 18);
* превью идёт по окну, которое сейчас впереди, а при старте область закрепляется за браузером.
  Нажатие «Старт» в окне программы больше не делает целью её саму;
* таймер Windows переводится в режим 1 мс (`timeBeginPeriod`), иначе `sleep` спит по 15,6 мс и
  превью дёргается;
* если объект не реагирует на клики (не прыгает) 1,5 с, это не червь. Программа его забывает и
  ждёт настоящего;
* интерфейс перерисовывает превью только при новом кадре, а плитки статистики — только при
  изменении значения.

## Требования

* Windows 10 (1903+) или Windows 11, x64.
* Python **3.10–3.13** с [python.org](https://www.python.org/downloads/). В стандартный установщик
  входит Tcl/Tk, нужный для интерфейса. При установке отметьте «Add python.exe to PATH».
  Если используется готовый `.exe`, Python не нужен.
* Права администратора **не требуются**. Есть одно исключение: если браузер запущен от имени
  администратора, программу тоже придётся запустить от администратора (иначе Windows блокирует
  ввод, см. «Ограничения»).

Зависимости (`requirements.txt`): `numpy`, `opencv-python-headless`, `mss`, а также `dxcam`
(только в Windows, это быстрый захват экрана через DXGI). Платные сервисы и API-ключи не нужны,
по сети программа ничего не отправляет.

## Установка

### Вариант 1 — `run.bat` (рекомендуется)

1. Скачайте репозиторий (кнопка **Code → Download ZIP**) и распакуйте его, например, в `C:\WormClicker`.
2. Запустите двойным щелчком **`run.bat`**.
   При первом запуске он сам создаст виртуальное окружение `.venv` и установит зависимости
   (1–3 минуты, нужен интернет). Затем откроется окно программы.
3. Дальше программа запускается тем же `run.bat` за секунду.

Если нужно видеть лог в консоли, используйте `run_console.bat`. Через него же доступны
дополнительные параметры: `run_console.bat --dry-run --debug`, `run_console.bat --benchmark`.

### Вариант 2 — вручную

```bat
cd C:\WormClicker
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python run_wormclicker.py
```

Параметры командной строки:

| параметр | назначение |
|---|---|
| `--dry-run` | тестовый режим: клики не отправляются |
| `--config PATH` | другой файл настроек |
| `--benchmark` | замеры производительности без интерфейса и без кликов |
| `--debug` | подробный лог |

### Вариант 3 — один файл `WormClicker.exe`

* **Собрать самому:** запустите `build_exe.bat`. Результат появится в `dist\WormClicker.exe`.
  Рядом будут лежать `config.default.json` и `practice\`.
* **Скачать из CI:** при каждом push GitHub Actions собирает exe на Windows-раннере и проверяет,
  что он запускается. Файл лежит во вкладке **Actions → последний запуск CI → Artifacts →
  `WormClicker-windows`**.

## Быстрый старт

1. Откройте игру в браузере (масштаб страницы лучше оставить 100%) и запустите программу
   (`run.bat`). Справа в окне сразу появится живое превью.
2. Перейдите в браузер и нажмите **F6** (или кнопку **«Старт / стоп»**). Статус сменится на
   «Поиск»: «жду движения: кликните по червю один раз».
3. **Кликните по червю сами один раз.** Он прыгнет, программа увидит движение маленького розового
   объекта, зафиксирует цель (в превью появится рамка «ЦЕЛЬ») и начнёт кликать по нему без
   остановки.
4. **F6** ещё раз — стоп, **F7** — аварийная остановка. Новые клики прекращаются сразу.
5. Если переключиться на другое окно (Alt+Tab), клики встанут на паузу и не уйдут в чужие
   программы. Когда вы вернётесь в браузер, они продолжатся сами.

Червя можно «показать» программе и до старта. Пока превью работает, программа уже следит за
экраном. Если кликнуть по червю, когда автоматизация выключена, цель запомнится, и после F6 клики
начнутся мгновенно.

Почему цель именно движение: на странице может быть много розового — текст, кнопки, свечение,
статичная картинка червя. Двигается же после клика только сам червь. Поэтому программа ничего не
делает, пока что-то маленькое и розовое не сдвинется. Клика наугад не бывает.

## Способ «по образцу»

Это запасной способ: на случай, если первый не срабатывает или червь в вашей игре почти не
двигается.

* **Обвести на превью.** Зажмите левую кнопку мыши на превью и обведите червя рамкой.
* **Под курсором.** Наведите курсор на червя в игре и нажмите **F8**. Либо на вкладке «Цель»
  нажмите «Под курсором через 3 с» и за 3 секунды наведите курсор.

Программа подстроит диапазон оттенков под настоящую палитру игры и запомнит размер и форму
объекта. Режим переключится на «по образцу», и цель будет находиться даже без движения (в том числе
сразу после старта). Если на экране несколько похожих объектов, выбирается наиболее похожий и
ближайший к прошлой позиции. Кнопка **«Сбросить цель»** вернёт стандартные цвета и режим ожидания.

## Скорость кликов

Вкладка **«Клики»**:

* **ползунок** с логарифмической шкалой: левый край — «Максимум», дальше 1 мс … 1000 мс;
* **быстрые кнопки:** Макс, 1, 5, 10, 25, 50, 100, 250 мс;
* **точное поле** «Свой интервал»: любое значение от 0 до 10 000 мс (0 = максимум).

Под ползунком видно, сколько это кликов в секунду (50 мс ≈ 20 кликов/с). Изменение применяется
сразу, даже во время работы, и сохраняется в `config.json` (`click_interval_ms`).

**«Максимум»** (по умолчанию) — каждый клик сразу после анализа нового кадра, без пауз. Реальная
частота упирается в скорость захвата экрана и поиска (на тестовом раннере это 130–180 кликов/с на
симуляторе, на вашем ПК может отличаться). Если игра не успевает засчитывать клики, увеличьте
интервал. Клики идут по расписанию (`время прошлого клика + интервал`), поэтому частота не
«уплывает» из-за времени обработки кадра.

Даже при большом интервале программа продолжает смотреть на экран между кликами. Каждый клик
отправляется по самой свежей позиции червя.

## Интерфейс

Одно окно в тёмной теме: всё управление слева, превью справа.

* **Шапка:** логотип, версия и цветной статус — Ожидание / Поиск / Работа / Пауза / Ошибка.
* **Карточка управления:** большая кнопка «Старт / стоп» с подсказкой горячей клавиши,
  переключатель «Тест без кликов» и строка с причиной текущего состояния.
* **Плитки статистики:** кликов/с, ≈ попаданий/с, кадров/с, кликов всего, ≈ попаданий,
  «кадр → клик, мс». Ниже мелким шрифтом — захват и анализ кадра в мс, потери цели, отброшенные
  объекты, время сессии и доля попаданий от кликов.
* **Вкладки:**
  * **Клики** — скорость (см. выше);
  * **Цель** — режим «По движению» / «По образцу», что запомнено (источник, размер, число
    прыжков), захват по курсору, сброс, размер цели в пикселях;
  * **Захват** — где искать (активное окно браузера, конкретный монитор, все мониторы), способ
    захвата (Авто / dxcam / mss), пауза без фокуса, частота превью (30/60/90/120), превью вкл/выкл;
  * **Клавиши** — переназначение горячих клавиш.
* **Превью:** живой кадр области поиска. Вокруг цели рисуется рамка «ЦЕЛЬ» со сходством, при клике
  появляется точка. В углу выводится HUD: частота кадров превью, состояние и область. Больше ничего
  не рисуется: ни других кандидатов, ни подписей «?». Всё оформление рисует Tk, поэтому кириллица
  отображается нормально.

**«≈ попадания»** — это **оценка**. Программа считает прыжки червя после кликов. Подтвердить
попадание напрямую сайт не даёт, точное число показывает счётчик самой игры. Кликов при
непрерывном режиме обычно заметно больше, чем попаданий: пока браузер перерисовывает червя, по нему
успевает уйти несколько кликов.

Окно программы исключено из захвата экрана (`WDA_EXCLUDEFROMCAPTURE`). Червь в превью не станет
целью, а точки под окном программы никогда не кликаются. Побочный эффект: окно программы не видно
на записях экрана и скриншотах. Скриншоты на диск программа не пишет.

## Горячие клавиши

| действие | по умолчанию |
|---|---|
| Старт / стоп | **F6** |
| Аварийная остановка | **F7** |
| Захват цели под курсором | **F8** |

Вкладка **«Клавиши»**: нажмите на клавишу напротив действия, затем новую клавишу или сочетание
(например, `Ctrl+Shift+F9`); Esc отменяет. Поддерживаются F1–F24, буквы, цифры, NumPad, Pause,
ScrollLock, Insert, Home, End, PageUp и PageDown с модификаторами Ctrl, Alt, Shift и Win.

Технически используется `RegisterHotKey` в отдельном потоке:

* клавиши работают глобально, в том числе когда в фокусе браузер;
* права администратора не нужны;
* флаг `MOD_NOREPEAT` и антидребезг 300 мс не дают удержанию F6 хаотично переключать режим;
* если клавишу заняла другая программа, рядом появится предупреждение.

## Безопасный тестовый режим

* **Тест без кликов** — переключатель в карточке управления или `--dry-run`. Всё работает как
  обычно, но мышь не нажимается. Червь в таком режиме никуда не прыгает, поэтому цель после
  первого обнаружения просто сопровождается: отбрасывания «не реагирующих» объектов в тестовом
  режиме нет.
* **Тренировочная мишень** `practice/index.html` работает локально, без сети. На ней тот же червь:
  при попадании он прыгает и поворачивается. Есть счётчик попаданий и промахов и помехи (частицы,
  розовый текст, розовая кнопка).

## Как программа находит цель

1. **Розовые пятна.** Кадр переводится в HSV, выделяются пиксели «розового» (оттенок с учётом
   перехода через красный, отдельно насыщенный, светлый и бордовый) и связные области подходящего
   размера. Глаза и зрачки включаются в силуэт. Всё это — один быстрый проход по уменьшенному кадру
   и точный анализ каждого пятна.
2. **Карта движения.** Для каждого пикселя помнится, когда он менялся в последний раз. Пятно
   считается «свежим», если большая часть его пикселей изменилась за последние 400 мс
   (`fresh_window_ms`, `min_fresh`). Неподвижный текст, кнопки, свечение и статичная копия червя
   свежими не бывают. Частицы отбрасываются по размеру. Слишком большие пятна (больше
   `max_target_area`) — по площади.
3. **Захват цели.** Первое свежее маленькое розовое пятно становится целью. Запоминается его
   «внешность»: площадь, цвет и форма (моменты Ху, не зависят от поворота).
4. **Сопровождение.**
   * Пока червь на месте (вы кликаете, а браузер ещё не перерисовал), цель — то же пятно.
   * Червь прыгнул: старое место пропало, где-то появилось свежее пятно, похожее по внешности, —
     это новая позиция. Засчитывается прыжок.
   * Анимация «ползания» на месте прыжком не считается: на месте меняется лишь несколько процентов
     пикселей, а при прыжке — больше 60%.
5. **Потеря и возврат.** Червь пропал — клики останавливаются (статус «цель потеряна»). Как только
   появится похожее свежее пятно, сопровождение продолжится.
6. **Не цель.** Если по объекту кликали 1,5 с (`unlock_after_ms`), а он ни разу не прыгнул, это не
   червь. Он попадает в список игнорируемых на 5 с, программа его забывает и ждёт настоящего.
7. **Окно сдвинули или изменили размер** — карта движения сбрасывается. Запомненный червь
   находится снова по внешности, даже без нового движения.

Режим **«по образцу»** заменяет шаги 2–3: цель — пятно, наиболее похожее на образец
(`sample_similarity`). Движение не требуется.

**Точка клика** — внутренняя точка силуэта (максимум distance transform по самим розовым
пикселям). Она остаётся внутри червя при любом повороте и изгибе.

## Цикл кликов

Один фоновый поток:

```
захват кадра → поиск цели → клик (если подошло время по интервалу) → захват → …
```

* **Непрерывно.** Прыжок не ждётся: пока цель видна, клики идут с заданным интервалом или с
  максимальной скоростью. Задержка отрисовки браузера (несколько мс) значит, что часть кликов
  придётся по червю, который вот-вот прыгнет. Это нормально и честно отражено в статистике
  (кликов больше, чем попаданий).
* **Без кликов наугад.** Нет цели — нет кликов. Клик всегда попадает внутрь области поиска и никогда
  не попадает в окно самой программы.
* **Безопасность.** В режиме «окно браузера» кликов нет, если браузер не в фокусе, свёрнут или
  закрыт. Второй экземпляр программы не запустится. Повторный старт не создаёт второй поток. После
  стопа ни одного клика не уходит (флаг и клик проверяются под одной блокировкой). При закрытии окна
  поток останавливается, захват освобождается, горячие клавиши снимаются.
* **Превью** публикуется тем же потоком, но не чаще выбранной частоты. Кадр уменьшается до размера
  панели в рабочем потоке. Интерфейс рисует рамку цели и передаёт готовые байты PPM в
  переиспользуемое изображение Tk, без PNG-кодирования и без создания новых объектов на каждый
  кадр. Поэтому цикл кликов от превью почти не замедляется.

**Мышь:** `SetCursorPos` (точный физический пиксель, работает с отрицательными координатами), затем
один вызов `SendInput` с нажатием и отпусканием. **Мультимонитор и DPI:** процесс объявлен
*Per-Monitor DPI Aware v2*, все координаты — физические пиксели виртуального рабочего стола.

## Производительность

Главная метрика — **прыжки червя (≈ попадания) в секунду**, а не число отправленных кликов.
Программа не утверждает, что кликает быстрее, чем позволяют игра, браузер, монитор и захват
экрана: реальные значения видны в окне.

Замер на своём ПК: `run_console.bat --benchmark`. Он показывает скорость поиска на синтетических
кадрах, реальную скорость захвата экрана (dxcam и mss) и сквозной цикл на встроенном симуляторе.
В симуляторе есть **статичная копия червя-приманка**, кликать по ней нельзя. Реальных кликов при
замере нет.

Windows-раннер GitHub Actions (`windows-latest`, виртуальная машина без GPU), прогон версии 2.0:

| замер | Python 3.12 | Python 3.11 |
|---|---|---|
| поиск цели 1920×1080, медиана | 8.1 мс | 13.1 мс |
| поиск цели 1280×720, медиана | 5.3 мс | 9.1 мс |
| захват mss 1024×768, медиана | 16.0 мс | 30.8 мс |
| захват dxcam 1024×768 | 0.06 мс без нового кадра (экран раннера статичен) | то же |
| симулятор, «максимум», без задержки отрисовки | **144 попаданий/с** = 144 клика/с | 136 / 136 |
| симулятор, «максимум», задержка отрисовки 30 мс | **30.7 попаданий/с** при 184 кликах/с | 30.7 / 179 |
| симулятор, интервал 20 мс | 50.0 попаданий/с = 50.0 кликов/с | то же |
| клики по статичной копии червя | 0 | 0 |

Linux-песочница разработки (2 vCPU, только синтетика, захвата экрана нет): поиск цели 5.8 мс
(1080p) / 3.4 мс (720p); симулятор — 178 попаданий/с без задержки, 30.7 попаданий/с при 220
кликах/с с задержкой 30 мс; 0 кликов по приманке.

Это синтетика: «попадание» засчитывает симулятор. Скорость в настоящей игре этими цифрами **не
гарантируется**. При задержке отрисовки 30 мс предел — около 1/0,03 ≈ 33 попаданий/с, сколько бы
кликов ни отправлялось.

На скорость в реальной игре сильнее всего влияют:

* задержка отрисовки браузера (обычно 1–2 кадра монитора, 7–17 мс на 60–144 Гц);
* метод захвата: DXGI (`dxcam`) обычно намного быстрее GDI (`mss`). Режим «Авто» пробует dxcam и
  при неудаче переходит на mss;
* размер области: режим «окно браузера» сканирует только клиентскую область, а не весь монитор.

## Настройки (`config.json`)

Файл создаётся рядом с программой при первом изменении настроек. Значения по умолчанию — в
`config.default.json` и `wormclicker/config.py`. Неизвестные ключи игнорируются, некорректные
значения заменяются допустимыми. Файл от версии 1 читается: горячие клавиши, область и цвета
сохраняются, превью включается.

| ключ | по умолчанию | описание |
|---|---|---|
| `hotkey_toggle` / `hotkey_stop` / `hotkey_calibrate` | `F6` / `F7` / `F8` | горячие клавиши |
| `click_interval_ms` | `0` | интервал между кликами, мс (0 — максимум) |
| `debug_view` | `true` | встроенное превью |
| `preview_fps` | `60` | частота превью (10–144) |
| `capture_area` | `window` | `window`, `monitor:0`, `monitor:1`, …, `all` |
| `capture_backend` | `auto` | `auto` (dxcam → mss), `dxcam`, `mss` |
| `require_focus` | `true` | пауза, если браузер не в фокусе |
| `dry_run` | `false` | тестовый режим без кликов |
| `idle_sleep_ms` | `2` | пауза между кадрами, когда нет ни цели, ни превью |
| `target.mode` | `motion` | `motion` — по движению, `sample` — по образцу |
| `target.fresh_window_ms`, `target.min_fresh` | `400`, `0.5` | что считать «движением» |
| `target.min_similarity`, `target.sample_similarity` | `0.45`, `0.6` | сходство с запомненной целью |
| `target.max_target_area` | `30000` | максимальная площадь цели, px |
| `target.lost_timeout_ms` | `300` | через сколько цель считается потерянной |
| `target.unlock_after_ms` | `1500` | объект без прыжков столько мс — не цель (0 — выкл.) |
| `detector.hue_ranges` | `[[140,179],[0,10]]` | оттенки «розового» (OpenCV H 0–179), подстраиваются образцом |
| `detector.min_saturation`, `min_value` | `60`, `70` | пороги насыщенности и яркости |
| `detector.min_area`, `max_area` | `120`, `60000` | площадь пятна, px |

## Ограничения

* **Настоящая игра не проверялась.** Ни у среды разработки, ни у CI не было доступа к сайту игры
  или её скриншоту. Поиск цели и цикл кликов проверены на синтетических кадрах и встроенном
  симуляторе, платформенный код и интерфейс — на Windows-раннере GitHub Actions. Перед
  рейтинговой игрой проверьте программу в тестовом режиме и на тренировочной мишени.
* Способ «по движению» требует, чтобы червь хотя бы раз сдвинулся. Если рядом с ним постоянно
  движется что-то другое маленькое и розовое (анимированная реклама, розовые частицы крупнее
  пары пикселей), программа может сначала выбрать его. Через 1,5 с без прыжков она его отбросит.
  Либо используйте способ «по образцу».
* Цвета по умолчанию подобраны по описанию игры. Если у настоящего червя другая палитра, его
  может не найти. В этом случае один раз сделайте образец (обвести на превью или F8).
* Если браузер или игра запущены **от имени администратора**, Windows (UIPI) блокирует ввод от
  обычной программы. Будет ошибка «SendInput заблокирован»; запустите программу тоже от
  администратора.
* dxcam захватывает область в пределах одного монитора. Для окна, растянутого на два монитора,
  автоматически используется mss.
* Исключение окна программы из захвата работает в Windows 10 2004 и новее.
* Игра может ограничивать частоту засчитываемых кликов. Программа это не обходит: она показывает
  измеренные прыжки.
* Глобальные горячие клавиши, режим «окно браузера» и реальные клики есть только в Windows. На
  других ОС работают тесты, бенчмарк и тестовый режим.

## Структура проекта

```
wormclicker/
  app.py          точка входа: DPI-awareness, таймер 1 мс, один экземпляр, запуск UI
  automation.py   цикл кликов (один поток), интервал по расписанию, превью, старт/стоп, статус
  target.py       выбор цели: карта движения, захват, сопровождение, прыжки, образец, «не цель»
  detector.py     розовые пятна, силуэт, точка клика (HSV, связные области, distance transform)
  capture.py      захват экрана: dxcam (DXGI) и mss (GDI), автоматический выбор
  mouse.py        клики: SetCursorPos + SendInput; DryRunMouse для тестового режима
  hotkeys.py      глобальные горячие клавиши (RegisterHotKey), разбор, антидребезг
  region.py       область поиска: окно браузера (за активным окном / закреплённое), мониторы
  geometry.py     прямоугольники, мониторы, отрицательные координаты
  calibration.py  подстройка цвета и размера по образцу
  stats.py        потокобезопасная статистика
  config.py       настройки, загрузка/сохранение JSON, миграция v1 → v2
  ui.py           главное окно (Tk): карточки, плитки, вкладки, встроенное превью
  widgets.py      собственные виджеты: кнопки, переключатели, ползунок, выпадающий список, тема
  formatting.py   форматирование статистики и шкалы интервала (тестируется без дисплея)
  debug_view.py   подготовка кадра превью (масштаб, рамка цели, PPM)
  winapi.py       обёртки ctypes над WinAPI
  sprite.py       эталонный пиксельный спрайт червя
  synthetic.py    синтетические сцены с помехами для тестов
  simulator.py    офлайн-симулятор игры (с приманкой) для тестов и бенчмарка
  benchmark.py    замеры производительности
tools/ui_screenshot.py   снимок окна в CI для проверки вёрстки
practice/index.html      тренировочная мишень
tests/                   тесты pytest
```
