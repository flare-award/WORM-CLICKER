# Worm Clicker

Автокликер для браузерной игры с розовым пиксельным червём. Программа находит червя на экране
с помощью компьютерного зрения (OpenCV, без нейросетей), кликает в точку внутри его силуэта и
после каждого прыжка ищет его заново. Повторно кликнуть по старым координатам она не может.

* Включение и выключение — **F6** (работает и тогда, когда в фокусе браузер). Аварийная остановка — **F7**.
  Калибровка по курсору — **F8**. Все клавиши можно переназначить.
* Червь распознаётся при любом угле поворота, в любом месте окна и на любом мониторе, в том числе
  на мониторах с отрицательными координатами и при разном масштабе DPI.
* Есть тестовый режим без кликов, визуальная отладка, подробная статистика и замеры задержек.
* Есть локальная тренировочная мишень `practice/index.html`: на ней всё можно проверить, не трогая
  настоящую игру.

> ⚠️ **О правилах игры.** Многие игры с таблицами лидеров запрещают автоматизацию. Прежде чем
> использовать программу в рейтинговой игре, прочитайте правила сайта: за бота могут обнулить
> результат или заблокировать аккаунт. Программа не обходит античит и защитные механизмы сайта,
> не изменяет страницу и не перехватывает сетевой трафик. Она смотрит на экран и двигает мышь,
> как обычный пользователь. Для проверки и настройки используйте тестовый режим и тренировочную
> мишень.

## Требования

* Windows 10 (1903+) или Windows 11, x64.
* Python **3.10–3.13** с [python.org](https://www.python.org/downloads/). В стандартный установщик
  входит Tcl/Tk, нужный для интерфейса. При установке отметьте «Add python.exe to PATH».
  Если используется готовый `.exe`, Python не нужен.
* Права администратора **не требуются**. Есть одно исключение: если браузер запущен от имени
  администратора, программу тоже придётся запустить от администратора (иначе Windows блокирует
  ввод, см. «Ограничения»).

Зависимости (`requirements.txt`): `numpy`, `opencv-python-headless`, `mss`, а также `dxcam`
(только в Windows, это быстрый захват экрана через DXGI). Платные сервисы и API-ключи не нужны,
по сети программа ничего не отправляет.

## Установка

### Вариант 1 — `run.bat` (рекомендуется)

1. Скачайте репозиторий (кнопка **Code → Download ZIP**) и распакуйте его, например, в `C:\WormClicker`.
2. Запустите двойным щелчком **`run.bat`**.
   При первом запуске он сам создаст виртуальное окружение `.venv` и установит зависимости
   (1–3 минуты, нужен интернет). Затем откроется окно программы.
3. Дальше программа запускается тем же `run.bat` за секунду.

Если нужно видеть лог в консоли, используйте `run_console.bat`. Через него же доступны
дополнительные параметры: `run_console.bat --dry-run --debug`, `run_console.bat --benchmark`.

### Вариант 2 — вручную

```bat
cd C:\WormClicker
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python run_wormclicker.py
```

Параметры командной строки:

| параметр | назначение |
|---|---|
| `--dry-run` | тестовый режим: клики не отправляются |
| `--config PATH` | другой файл настроек |
| `--benchmark` | замеры производительности без интерфейса и без кликов |
| `--debug` | подробный лог |

### Вариант 3 — один файл `WormClicker.exe`

* **Собрать самому:** запустите `build_exe.bat`. Результат появится в `dist\WormClicker.exe`.
  Рядом будут лежать `config.default.json` и `practice\`.
* **Скачать из CI:** при каждом push GitHub Actions собирает exe на Windows-раннере и проверяет,
  что он запускается. Файл лежит во вкладке **Actions → последний запуск CI → Artifacts →
  `WormClicker-windows`**.

## Быстрый старт

1. Откройте игру в браузере. Масштаб страницы лучше оставить 100%.
2. Запустите программу (`run.bat`). Автоматизация при старте **выключена**.
3. *(Рекомендуется, делается один раз)* **Калибровка.** Наведите курсор на червя и нажмите **F8**.
   Программа подстроит диапазон оттенков и ожидаемый размер червя под вашу игру, монитор и масштаб.
   Результат появится на вкладке «Детектор» и сохранится в `config.json`. Можно также нажать кнопку
   «Калибровать по курсору (3 с)» на вкладке «Детектор» и за 3 секунды навести курсор на червя.
4. Перейдите в окно браузера и нажмите **F6**. Начнётся охота. По умолчанию сканируется клиентская
   область окна браузера, которое было активным в момент нажатия F6.
5. Чтобы остановить, нажмите **F6** ещё раз (или **F7**, аварийная остановка). Новые клики
   прекращаются сразу.
6. Если переключиться на другое окно (Alt+Tab), автоматизация встанет на паузу и не будет кликать
   в чужие программы. Когда вы вернётесь в браузер, она продолжится сама.

Если червь не находится, в строке статуса будет написана причина: «нет розовых пикселей в кадре»,
«кандидаты отклонены: низкая уверенность 0.42», «окно браузера не в фокусе» и т. п. Клики
наугад программа не делает. Подробности видны в режиме **Визуальная отладка**.

## Безопасный тестовый режим

* **Тест без кликов.** Это флажок в главном окне или параметр `--dry-run`. Захват, обнаружение и
  решения о клике работают как обычно, статистика считается, но события мыши не отправляются.
  Так можно проверить распознавание в настоящей игре, не взаимодействуя с ней.
* **Тренировочная мишень.** Откройте `practice/index.html` в браузере, файл работает локально,
  без сети. Там нарисован тот же червь. Если попасть по нему, он прыгает в случайное место и
  поворачивается на случайный угол. Есть счётчик попаданий и промахов, а также переключатели:
  анимация «ползания», плавное перемещение, исчезновение после попадания, помехи (частицы, розовый
  текст, розовая кнопка). На этой странице удобно проверить скорость и надёжность на своём ПК.

## Горячие клавиши и их настройка

| действие | по умолчанию |
|---|---|
| Старт / стоп | **F6** |
| Аварийная остановка | **F7** |
| Калибровка по курсору | **F8** |

Как переназначить: вкладка **Управление** → кнопка **«Назначить»** напротив действия → нажмите
новую клавишу или сочетание (например, `Ctrl+Shift+F9`), Esc отменяет. Поддерживаются F1–F24,
буквы, цифры, цифры на NumPad, Pause, ScrollLock, Insert, Home, End, PageUp и PageDown вместе с
модификаторами Ctrl, Alt, Shift и Win. Настройка применяется сразу и сохраняется в `config.json`
(ключи `hotkey_toggle`, `hotkey_stop`, `hotkey_calibrate`).

Технически используется `RegisterHotKey` (WinAPI) в отдельном потоке:

* клавиша работает глобально, в том числе когда в фокусе браузер;
* права администратора не нужны;
* нажатие перехватывается, поэтому F6 не переводит фокус браузера в адресную строку;
* флаг `MOD_NOREPEAT` и программный антидребезг (300 мс) не дают удержанию клавиши хаотично
  переключать режим;
* если клавишу уже заняла другая программа, рядом с полем появится предупреждение. Тогда выберите
  другую.

## Интерфейс и статистика

Компактное окно в тёмной теме с тремя вкладками.

**Статистика**

| показатель | смысл |
|---|---|
| Статус | Ожидание / Поиск / Работа / Пауза / Ошибка, ниже указана причина |
| Клики отправлено | фактически отправленные клики |
| **Прыжки после клика (≈ попадания)** | клик, после которого червь исчез с места клика и появился в другом месте. Это **оценка** попаданий: сайт не даёт надёжного способа подтвердить попадание. Точное число показывает счётчик самой игры |
| Кликов/с, прыжков/с, средний кликов/с | измеренные частоты: за последнюю секунду и за сессию |
| Кадров/с обработано | частота цикла «захват → обнаружение» |
| Захват кадра, мс / Детекция, мс | средняя задержка этапов |
| Кадр → клик, мс | от начала захвата кадра до отправки клика |
| Клик → новая позиция, мс | от клика до обнаружения червя на новом месте. Сюда входит реакция игры, браузера и монитора |
| Потерь цели / повторных обнаружений | сколько раз червь пропадал дольше 300 мс и за какое время находился снова |
| Клик без прыжка (промах?) | после клика червь остался на месте |
| Устаревших кадров пропущено | кадры, на которых червь ещё виден на месте последнего клика (подробнее ниже) |
| Статичных ложных целей | места, исключённые после нескольких кликов без реакции |

**Управление:** горячие клавиши, область поиска (окно браузера, конкретный монитор или все
мониторы), способ захвата (auto, dxcam или mss), пауза при потере фокуса.

**Детектор:** порог уверенности, минимальная и максимальная площадь червя, шаг грубого поиска,
число кадров подтверждения, время ожидания прыжка, необязательный лимит кликов в секунду, пауза
поиска без цели, калибровка и её сброс.

**Визуальная отладка** открывается флажком на вкладке «Статистика», в отдельном окне. В нём видны
захваченный кадр, контур червя, ограничивающие прямоугольники всех кандидатов, точка клика
(красное перекрестие), оценка уверенности, время обработки кадра, причина отклонения каждого
кандидата, а также зоны, исключённые как статичные ложные цели. Отладка обновляется примерно 4 раза
в секунду и только тогда, когда окно открыто. Кадр рисуется в потоке интерфейса, поэтому цикл
кликов это не замедляет. Скриншоты на диск не записываются.

Окна программы исключены из захвата экрана (`WDA_EXCLUDEFROMCAPTURE`). Поэтому червь в окне
отладки не будет найден, а точки под окнами программы никогда не кликаются. Побочный эффект:
окна программы не видны и в записях экрана и на скриншотах.

## Как работает обнаружение

Используются классические методы компьютерного зрения, и они устойчивы к повороту и масштабу.
Сравнение с одним шаблоном **не используется**.

1. **Грубый проход по всему кадру.** Кадр уменьшается методом ближайшего соседа (шаг 2 по
   умолчанию). У пиксель-арта цвета при этом не смешиваются. Затем выполняется сегментация
   «розового» в HSV: оттенок проверяется по таблице, которая учитывает переход через красный
   (H 140…179 и 0…10). Отдельно учитываются насыщенный розовый, светло-розовый и бордовый. Маска
   слегка расширяется, после чего выделяются связные области. Мелкие точки (частицы) отбрасываются
   сразу.
2. **Точный анализ каждого кандидата** в полном разрешении:
   * **силуэт** — розовые пиксели вместе со светлыми (глаза), с морфологическим закрытием и
     заливкой внутренних дыр (зрачков);
   * **цвет** — доля розового, наличие нескольких оттенков (светлый, средний, тёмный) и
     компактная палитра, характерная для пиксель-арта, в отличие от градиентов и свечения;
   * **глаза** — светлые прямоугольные пятна внутри силуэта, в которых есть **замкнутый тёмный
     зрачок**. Вокруг пятна должен быть розовый, само пятно должно лежать в глубине головы. Пара
     похожих глаз рядом друг с другом даёт самый сильный признак;
   * **геометрия, не зависящая от поворота**: соотношение сторон `minAreaRect`, заполненность,
     расстояние по моментам Ху до эталонного силуэта (`cv2.matchShapes`);
   * **размер** — после калибровки учитывается мягкое ограничение по ожидаемой площади.

   Из признаков складывается оценка уверенности от 0 до 1. Кандидаты ниже порога (по умолчанию
   0.58) отклоняются, и причина записывается для отладки.
3. **Точка клика.** Если силуэт чистый, это внутренняя точка тела: максимум distance transform
   ближе всего к середине между головой и центром тела. Такая точка остаётся внутри червя при
   любом повороте и при изогнутой анимации. Если червь «слился» с розовым текстом или кнопкой,
   клик делается между глазами, то есть гарантированно по голове.
4. **Быстрые пути.** Вердикт по статичным отклонённым элементам страницы (текст, кнопки)
   переиспользуется, пока их очертания не меняются. Если включено подтверждение по нескольким
   кадрам, поиск сначала идёт в окрестности последней позиции, а при неудаче — снова по всему
   кадру.

Эталонного скриншота игры в репозитории нет. Спрайт червя (`wormclicker/sprite.py`) нарисован
по текстовому описанию: розовое тело трёх оттенков, бордовый контур, два светлых прямоугольных
глаза с тёмными зрачками. Описание служит ориентиром, а не жёстким шаблоном. Поэтому важна
калибровка (F8): она подстраивает цвета и размер под настоящую игру.

## Логика кликов и защита от «старых» координат

Цикл работает в **одном** фоновом потоке:

```
захват свежего кадра → поиск всех кандидатов → оценка → выбор лучшего → точка внутри силуэта
→ клик → сразу захват следующего кадра → …
```

* **Каждый клик основан на свежем обнаружении.** Искусственных задержек нет.
* **Устаревшие кадры.** После клика браузеру и системе нужно несколько миллисекунд, чтобы
  нарисовать червя на новом месте. В это время захват ещё возвращает старую картинку. Пока на
  месте последнего клика виден червь в той же позе, кадр считается устаревшим и **клик не
  отправляется**, даже если где-то есть другой кандидат. Если червь не ушёл за 250 мс
  (`stale_timeout_ms`), значит клик не засчитан, и разрешается повторная попытка.
* **Новая позиция рядом со старой** определяется по изменению угла и площади.
* **Захват через DXGI (dxcam)** сообщает, что на экране ничего не изменилось. Тогда старый кадр не
  обрабатывается как новый, а повторно используется прошлый результат обнаружения.
* **Статичная картинка червя** на странице, например логотип: место, по которому кликнули 4 раза
  подряд без прыжка, исключается на 15 секунд, и охота продолжается за настоящим червём.
* **Потеря цели** (исчезновение, анимация, перекрытие): клики не отправляются, пока червь снова не
  найден с достаточной уверенностью. Ведётся статистика потерь и повторных обнаружений. Через
  0.5 с без цели поиск засыпает на 2 мс между кадрами, чтобы не нагружать процессор.
* **Безопасность:** клик всегда попадает внутрь сканируемой области. В режиме окна браузера
  кликов нет, если браузер не в фокусе, свёрнут или закрыт. Перемещение и изменение размера окна
  отслеживаются каждые 250 мс. Второй экземпляр программы не запустится (именованный mutex).
  Повторный старт не создаёт второй поток. После `stop()` гарантированно не уходит ни одного клика
  (проверка флага и клик выполняются под одной блокировкой). При закрытии окна поток останавливается,
  захват освобождается, горячие клавиши снимаются.

**Мышь:** `SetCursorPos` ставит курсор точно в нужный физический пиксель (работает с отрицательными
координатами). Затем один вызов `SendInput` отправляет нажатие и отпускание левой кнопки. Массив
`INPUT` создаётся один раз, поэтому на каждый клик нет выделений памяти.

**Мультимонитор и DPI.** Процесс объявляет себя *Per-Monitor DPI Aware v2*. Поэтому захват,
координаты окон и курсора задаются в физических пикселях виртуального рабочего стола, включая
мониторы слева или сверху от основного (отрицательные координаты) и мониторы с разным масштабом.

## Производительность

Главная метрика — **успешные попадания в секунду**, а не число отправленных событий. Программа не
утверждает, что кликает быстрее, чем позволяют игра, браузер, монитор и захват экрана: реальные
значения видны в окне статистики.

Чтобы замерить на своём ПК, запустите `run_console.bat --benchmark`. Замер покажет скорость
детектора на синтетических кадрах 1080p и 720p, реальную скорость захвата экрана через dxcam и mss
и сквозной цикл на встроенном симуляторе игры. Реальных кликов при этом нет.

Результаты в среде разработки (Linux-песочница, 2 vCPU, **только синтетические кадры**, захвата
экрана нет):

| замер | результат |
|---|---|
| детектор, кадр 1920×1080 с помехами (кадры меняются) | ≈ 6–7 мс |
| детектор, статичная сцена (типичный случай игры) | ≈ 3–4 мс |
| симулятор, игра без задержки отрисовки | ≈ 190 попаданий/с, точность 100%, 0 кликов по старой позиции |
| симулятор, задержка отрисовки 30 мс | ≈ 28 попаданий/с (предел ≈ 1 / задержку), 0 кликов по старой позиции |

Результаты на Windows-раннере GitHub Actions (`windows-latest`, виртуальная машина без GPU,
Python 3.12; на 3.11 результаты такие же в пределах ±5%):

| замер | результат |
|---|---|
| детектор, 1920×1080 / 1280×720 | медиана 13.0 / 9.7 мс, найден в 60/60 кадров |
| захват dxcam 1024×768 | 0.06 мс, если кадр не изменился (новый кадр раннер почти не выдаёт: экран статичен) |
| захват mss 1024×768 | медиана 16 мс, p95 32 мс |
| симулятор, без задержки отрисовки | **137.7 попаданий/с**, точность 100%, 0 кликов по старой позиции, кадр→клик 7.0 мс |
| симулятор, задержка отрисовки 30 мс | **25.3 попаданий/с**, точность 100%, 0 кликов по старой позиции |

Это синтетика: «попадание» засчитывает симулятор. Скорость в настоящей игре этими цифрами
**не гарантируется**.

В реальной игре на скорость сильнее всего влияют:

* задержка отрисовки браузера (обычно 1–2 кадра монитора: 7–17 мс на 60–144 Гц);
* метод захвата: DXGI (`dxcam`) обычно быстрее GDI (`mss`). Режим `auto` пробует dxcam и
  автоматически переходит на mss;
* размер сканируемой области. Режим «окно браузера» сканирует только клиентскую область, а не весь
  монитор.

Советы: используйте режим «окно браузера», масштаб 100% и калибровку. Если игра теряет клики при
слишком частом нажатии, задайте «Лимит кликов/с».

## Настройки (`config.json`)

Файл создаётся рядом с программой при первом изменении настроек. Значения по умолчанию лежат в
`config.default.json` и в коде (`wormclicker/config.py`). Неизвестные ключи игнорируются,
некорректные значения заменяются допустимыми.

| ключ | по умолчанию | описание |
|---|---|---|
| `hotkey_toggle` / `hotkey_stop` / `hotkey_calibrate` | `F6` / `F7` / `F8` | горячие клавиши |
| `capture_area` | `window` | `window`, `monitor:0`, `monitor:1`, …, `all` |
| `capture_backend` | `auto` | `auto` (dxcam → mss), `dxcam`, `mss` |
| `require_focus` | `true` | пауза, если окно браузера не в фокусе |
| `dry_run` | `false` | тестовый режим без кликов |
| `debug_view` | `false` | окно визуальной отладки |
| `idle_sleep_ms` | `2` | пауза между кадрами, если цели нет дольше 0.5 с |
| `detector.hue_ranges` | `[[140,179],[0,10]]` | оттенки «розового» (OpenCV H 0–179) |
| `detector.min_saturation`, `min_value` | `60`, `70` | пороги насыщенности и яркости |
| `detector.min_area`, `max_area` | `120`, `60000` | площадь силуэта, px |
| `detector.expected_area` | `0` | заполняется калибровкой |
| `detector.confidence_threshold` | `0.58` | порог уверенности |
| `detector.downscale` | `2` | шаг грубого поиска (1 — для очень мелкого червя) |
| `tracker.stale_timeout_ms` | `250` | ожидание прыжка после клика |
| `tracker.lost_timeout_ms` | `300` | через сколько цель считается потерянной |
| `tracker.stable_frames` | `1` | кадров подтверждения перед кликом |
| `tracker.max_cps` | `0` | лимит кликов в секунду (0 — без лимита) |
| `tracker.blacklist_after`, `blacklist_ttl_s` | `4`, `15` | исключение статичных ложных целей |

## Ограничения

Честный список того, что проверено, а что нет:

* **Настоящая игра не проверялась.** Ни среда разработки, ни CI не имели доступа к сайту игры и к
  её скриншоту. Детектор, трекер и цикл проверены на синтетических кадрах и встроенном симуляторе.
  Платформенный код Windows проверен на раннере GitHub Actions. Перед рейтинговой игрой проверьте
  программу в тестовом режиме, на тренировочной мишени и с калибровкой.
* Цвета по умолчанию подобраны по описанию. Если у настоящего червя другая палитра, его может не
  найти до калибровки. В этом случае нажмите F8, наведя курсор на червя.
* Если червь вплотную перекрывает большие розовые элементы страницы (крупный розовый текст,
  свечение), уверенность иногда падает ниже порога. Тогда программа **не кликает** и ждёт, клика
  наугад не будет. В синтетическом эксперименте (1200 случайных положений червя среди помех)
  таких случаев было 4 (0,3%), ложных кликов — 0.
* Очень мелкий червь (меньше ~120 px площади) требует уменьшить `min_area` и поставить
  `downscale = 1`.
* Если браузер или игра запущены **от имени администратора**, Windows (UIPI) блокирует ввод от
  обычной программы. Будет показана ошибка «SendInput заблокирован»; запустите программу тоже от
  администратора.
* dxcam захватывает область в пределах одного монитора. Если окно растянуто на два монитора, для
  таких кадров автоматически используется mss.
* Исключение окон программы из захвата (`WDA_EXCLUDEFROMCAPTURE`) работает в Windows 10 2004 и
  новее. В более старых версиях точки под окнами программы всё равно не кликаются.
* Игра может ограничивать частоту засчитываемых кликов. Программа это не обходит: она измеряет
  фактические прыжки.
* Глобальные горячие клавиши, режим «окно браузера» и реальные клики реализованы только для
  Windows. На других ОС работают тесты, бенчмарк и тестовый режим.

## Тестирование и результаты проверки

```bat
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest -v
```

В `tests/` 124 теста (на других ОС Windows-тесты пропускаются):

| область | что проверяется |
|---|---|
| детектор | исходное положение; углы 0, 15, 30, 45, 90, 135, 180, 225, 270, 315, 360° и произвольные, с резкими и сглаженными краями; масштаб пикселя 2–10; 120 случайных сцен (позиция, угол, масштаб, анимация); анимация «ползания»; углы и края кадра; поиск по всему кадру; отсутствие ложных срабатываний на 60 сценах только с помехами (белый и розовый текст, розовая кнопка, частицы, свечение, иконка); резкий прыжок; исчезновение; BGRA-кадры; откат с неверной подсказки ROI; червь, слипшийся с розовым текстом |
| трекер | пропуск устаревших кадров; подтверждение прыжка; повтор после тайм-аута; новая поза рядом; исчезновение и повторное обнаружение; исключение статичной ложной цели и его истечение; лимит CPS; подтверждение по кадрам |
| цикл автоматизации (сквозной, на симуляторе) | охота на мониторе с отрицательными координатами; **ноль кликов по старой позиции** при задержке отрисовки 30 мс и отстающем захвате; отсутствие кликов, пока червь скрыт; статистика потерь; старт в выключенном состоянии и переключение; **один рабочий поток** при 8 одновременных стартах; корректное завершение с освобождением захвата; ошибки мыши и захвата приводят в состояние «Ошибка» без кликов; пауза при недоступной области; запрет кликов под окнами программы; тестовый режим; калибровка; отладочный кадр |
| горячие клавиши | разбор сочетаний; преобразование Tk-событий; антидребезг; **удержание F6 = одно переключение**, повторное нажатие останавливает, F7 — аварийная остановка |
| геометрия и область поиска | виртуальный рабочий стол с мониторами слева и сверху (отрицательные координаты); окно частично за экраном; перевод координат и ограничение рамками; выбор окна браузера, ожидание при фокусе на самой программе, отслеживание перемещения, потеря фокуса, свёрнутое окно |
| конфигурация и калибровка | сохранение и загрузка; устойчивость к испорченному файлу; `config.default.json` совпадает с кодом; калибровка находит червя **другой палитры**, которого не видит детектор с настройками по умолчанию |
| Windows (только в CI) | размер структуры `INPUT`, вызовы WinAPI, регистрация и снятие `RegisterHotKey`, захват через mss и dxcam, **дымовой тест интерфейса Tk**, запуск собранного `.exe` |

**Результаты:**

* Linux-песочница, Python 3.11: **117 passed, 6 skipped**. Пропущены Windows-тесты и тесты Tk:
  в песочнице нет дисплея и tkinter.
* GitHub Actions `windows-latest`, Python 3.11 и 3.12: **124 passed, 0 skipped**. Сюда входят
  структуры WinAPI, `RegisterHotKey`, захват через mss и dxcam и дымовой тест интерфейса Tk.
  После тестов выполняется замер производительности (результаты в разделе «Производительность»),
  затем сборка `WormClicker.exe` (61 МБ). Собранный exe запускается в режиме `--dry-run` и
  10 секунд работает без ошибок. Конфигурация — `.github/workflows/ci.yml`, итоги каждого прогона
  видны во вкладке Actions.
* Linux CI (ubuntu-latest): тесты проходят, Windows-специфичные пропускаются.

Проверка на реальной игре **не проводилась**: настоящих кадров игры не было. Всё, что касается
распознавания, проверено на синтетических данных.

## Структура проекта

```
wormclicker/
  app.py          точка входа: DPI-awareness, защита от второго экземпляра, запуск UI
  automation.py   цикл автоматизации (один рабочий поток), старт/стоп, статус, отладочный кадр
  detector.py     детектор червя (HSV, связные области, глаза, геометрия, моменты Ху)
  tracker.py      решение о клике: устаревшие кадры, прыжки, потери, исключение ложных целей
  capture.py      захват экрана: dxcam (DXGI) и mss (GDI), автоматический выбор
  mouse.py        клики: SetCursorPos + SendInput; DryRunMouse для тестового режима
  hotkeys.py      глобальные горячие клавиши (RegisterHotKey), разбор, антидребезг
  region.py       область поиска: окно браузера, монитор, все мониторы
  geometry.py     прямоугольники, мониторы, отрицательные координаты
  calibration.py  калибровка цвета и размера по объекту под курсором
  stats.py        потокобезопасная статистика (частоты, EMA-задержки)
  config.py       настройки по умолчанию, загрузка и сохранение JSON
  ui.py           интерфейс Tkinter (тёмная тема)
  debug_view.py   разметка кадра для визуальной отладки
  winapi.py       обёртки ctypes над WinAPI
  sprite.py       эталонный пиксельный спрайт червя (аналог описания)
  synthetic.py    синтетические сцены с помехами для тестов
  simulator.py    офлайн-симулятор игры для сквозных тестов и бенчмарка
  benchmark.py    замеры производительности (--benchmark)
practice/index.html  локальная тренировочная мишень
tests/               тесты pytest
run.bat, run_console.bat, setup.bat, build_exe.bat   запуск, установка и сборка в Windows
config.default.json  настройки по умолчанию
```

Приватность: программа не собирает данные и не обращается к сети. Кадры экрана обрабатываются
только в памяти и не записываются на диск.
